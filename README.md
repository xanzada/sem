# SEM — автоматический оператор заявок

SEM — это worker-бот на Playwright с веб-панелью управления: обрабатывает заявки на сайте
(находит → открывает → проверяет статус → принимает → подтверждает результат) и **никогда не теряет
рабочее состояние** из-за проверок безопасности, истёкшей сессии или перезапуска сервера.

Ключевой принцип: `ПРОВЕРКА БЕЗОПАСНОСТИ ≠ ОТКАЗ БОТА` — это временное состояние workflow.

## Возможности

- 🖥 Веб-панель (RU, dark theme, mobile-first): статус в реальном времени, живая лента действий,
  аналитика (сколько заявок принято и с какой скоростью), настройки, журнал инцидентов, VNC.
- ⏯ Управление: Старт / Пауза / Стоп, ползунок скорости бота (×0.25…×3).
- 🔐 Автоматический вход при потере сессии; если не получилось — уведомление в Telegram и ожидание оператора.
- 🛡 При появлении проверки безопасности бот НЕ кликает ничего, НЕ перезагружает страницу и НЕ создаёт
  новый браузер — он сохраняет checkpoint и ждёт, пока сайт сам пропустит его, затем перепроверяет состояние.
- ♻️ Защита от дублей: перед каждым критическим действием пишется intent в базу (action ledger).
  После любого прерывания SEM сначала читает фактический статус заявки на сайте и никогда
  не повторяет уже выполненное действие.
- 💾 Checkpoints в SQLite: workflow_id, application_id, шаг, URL, скриншот. Рестарт контейнера/VPS
  возобновляет работу с последней безопасной точки.
- ❤️ Keep-alive: лёгкая активность без навигации, чтобы сайт не разлогинил сессию при простое.

## Встроенный демо-сайт (для теста)

Внутри SEM есть учебный сайт-мишень `/site` — точная копия типичного кабинета заявок:

- вход по логину/паролю (`admin` / `12345678Ss`);
- сессия истекает через 10 минут неактивности (как на реальном сайте);
- периодически появляется страница «Just a moment… Проверка браузера» — бот честно ждёт её окончания;
- новые заявки появляются сами, у каждой статус «В обработке» → кнопка «Принять».

Поэтому в Docker SEM по умолчанию работает в **боевом режиме против демо-сайта**
(`SITE_URL=http://127.0.0.1:8080/site`) — вы в VNC видите настоящий Chromium, который
логинится, листает список и принимает заявки. Когда появится реальный сайт, просто
поменяйте `SITE_URL`, `SITE_USERNAME`, `SITE_PASSWORD` в Environment и задайте селекторы.

## Переменные окружения (Dokploy → Environment)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SEM_MODE` | `live` | `live` / `simulation` |
| `AUTOSTART` | `true` | Запускать бота при старте контейнера |
| `SITE_URL` | `http://127.0.0.1:8080/site` | Адрес целевого сайта |
| `SITE_USERNAME` / `SITE_PASSWORD` | `admin` / `12345678Ss` | Учётка сайта |
| `SELECTORS_JSON` | демо-селекторы | CSS-селекторы реального сайта |
| `PANEL_USER` / `PANEL_PASSWORD` | `admin` / `12345678Ss` | Доступ к панели (Basic Auth) |
| `DEMO_SESSION_MINUTES` | `10` | Таймаут сессии демо-сайта |
| `SPEED` | `1` | Множитель скорости (×0.25…×3) |
| `KEEPALIVE_SEC` | `180` | Интервал keep-alive |
| `SECURITY_TIMEOUT_MIN` | `30` | Лимит ожидания проверки до SAFE_STOP |
| `TELEGRAM_TOKEN` / `TELEGRAM_CHAT_ID` | — | Уведомления |

ENV-переменные (из `.env` или Dokploy Environment) имеют приоритет — **но только если они явно заданы**.
Если переменная не задана, действует значение из панели. Пароли в git/логи не попадают.

## 🕒 График работы

Настройки → «График работы»: Включён + часы (например 9→21). Бот сам ставит паузу вне графика,
закрывает браузер (сервер отдыхает), утром открывает его с сохранённой сессией и продолжает работу.

## 🎯 Режим обучения — ботты өзіңіз оқытыңыз (кодсыз)

Сайттың дизайны өзгергенде немесе жаңа сайт қосқанда **программист қажет емес**:

1. Панель → Настройки → «🎯 Оқыту режимі» → URL енгизіп **«Бастау»**
2. **VNC вкладкасына** өтіңіз — сол жерде нақты сайт ашылады, тінтуір крестикке айналады
3. Ботқа керек элементтерді **тінтуірмен басыңыз**: заявка жолын, «Принять» батырмасын, статус белгісін…
   - Әр басу панельге түседі — бот элементтің бірнеше дұрыс селектор нұсқасын автоматты жинайды
4. Әр элементке **рөлін** таңдаңыз: 📋 Заявка жолы / 🔗 Ашу / 🟡 Күтуде / 🟢 Қабылданған / ✅ Принять
5. **«💾 Сақтау»** — селекторлар жаңартылып, бот жаңа интерфейспен жұмыс істейді

Қате бассаңыз — рөлін «ешқандай» етіп қойып, қайтадан басасыз.

Селекторлар массив болып сақталады: ескі нұсқалар да қалады, сайт кейін өзгерсе бот резервті өзі сынап көреді.

## Селектор денсаулығы

Настройки-де **«🧪 Селекторларды тексеру»** — сайттағы элементтердің тірі екенін бірден көрсетеді.
Элемент табылмаса бот: скрин сақтайды → Telegram хабарлайды → заявкаларды қолдамай қауіпсіз тоқтайды.

## Быстрый старт (локально)

```bash
npm install
npm run build
HEADLESS=true PORT=8080 npm start
# панель: http://localhost:8080
```

По умолчанию включён демо-режим (`simulation`) — SEM имитирует обработку заявок, включая редкие
«проверки безопасности» и «потери сессии», чтобы показать все состояния интерфейса.

## Docker

```bash
docker compose up -d --build
```

- Панель: порт `8080`
- noVNC: порт `6080` (только localhost на хосте; наружу — через SSH-туннель или reverse-proxy с авторизацией)
- Профиль браузера и база данных: папка `./data` (volume) — переживают перезапуск контейнера.

## Dokploy

1. Создайте приложение из GitHub-репозитория (`xanzada/sem`, Dockerfile в корне).
2. Порт: `8080`. Домен: `sem.aihub.software`.
3. Environment variables — см. таблицу выше (минимум: `SITE_URL`, `SITE_USERNAME`,
   `SITE_PASSWORD`, `PANEL_PASSWORD`). Значения ENV приоритетнее настроек из UI.
4. noVNC встроен в тот же порт через путь `/vnc/vnc.html?autoconnect=1&resize=scale&path=vnc/websockify`
   и доступен из панели (вкладка «VNC»).

## Состояния бота

| Состояние | Значение |
|---|---|
| 🟢 Работает | Нормальная обработка заявок |
| 🟡 Пауза | Остановлено оператором (кнопка ⏸) |
| 🔐 Требуется вход | Сессия истекла: идёт автологин либо ждёт оператора |
| 🛡 Ожидание проверки | Сайт показал security challenge — ждём его завершения |
| 🟠 Требуется внимание | Нестандартная ситуация, нужен оператор (VNC/журнал) |
| 🔴 Ошибка | Сбой цикла, будет повтор автоматически |
| ⏸ Остановлен | Полностью остановлен, checkpoint сохранён |

## Архитектура

```
src/
  index.ts       bootstrap, graceful shutdown
  server.ts      Fastify REST API + WebSocket live feed + static UI
  engine.ts      конечный автомат состояний, основной цикл OBSERVE→CLASSIFY→ACT→VERIFY→CHECKPOINT
  workflow.ts    драйверы: DemoDriver (симуляция) и LiveHttpDriver (боевой, по селекторам)
  classifier.ts  классификация страницы: NORMAL / AUTH / SECURITY / UNEXPECTED
  browser.ts     один постоянный Chromium-профиль (launchPersistentContext)
  ledger.ts      action intents — защита от повторных нажатий
  checkpoint.ts  точки восстановления workflow
  analytics.ts   статистика принятых заявок
  telegram.ts    уведомления
public/          панель (vanilla JS, тёмная тема, RU, mobile-first)
```
